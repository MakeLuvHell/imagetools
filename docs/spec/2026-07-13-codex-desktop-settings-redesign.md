# Codex Desktop 风格设置页重设计

## 目标

将现有设置页从稀疏、表单常驻的管理后台式界面，重设计为接近 Codex Desktop 完成度的桌面设置体验。改版只覆盖现有 Provider 与本地数据能力，不增加无关设置分类，不改变后端 API、数据库结构或存储迁移语义。

## 背景

当前设置页已经使用独立工作区和垂直导航，但仍存在以下问题：

- 选中导航使用大块品牌蓝，与主工作台的克制中性色不一致。
- Provider 列表与新增表单永久并排，默认页面被空表单占据，信息层级薄弱。
- 页面内容横向分散、纵向留白失衡，在 `1280x860` 下仍像未完成的后台表单。
- Provider 行内编辑、默认状态、删除和 API Key 状态缺少统一的任务边界。
- 本地数据页长期展示路径输入、复制选项和提交按钮，没有先表达当前状态与变更影响。
- 表单错误依赖脱离上下文的 Toast，缺少稳定的加载、空数据、提交中、失败和待重启状态。

## 用户确认方向

- 视觉与交互基准为 Codex Desktop，而不是 Windows 系统设置、Linear 或 Raycast。
- 本轮只重做 Provider 与本地数据，不新增通用、外观、快捷键等分类。
- 采用“列表管理 + 按需弹窗编辑”，不保留常驻主从表单，也不使用页面内展开编辑。
- Provider 与会话、生成记录、参考图和生成图片继续放在同一个工作区数据目录中。
- 设置页保持独立工作区；返回后恢复到打开设置前的工作台和触发控件。

## 范围

- 重构设置页的信息架构、HTML 语义和 CSS 视觉层级。
- 将 Provider 默认页面改为可扫描的列表管理界面。
- 将 Provider 新增和编辑移入独立对话框。
- 将设为默认和删除收拢到 Provider 行操作菜单；删除增加明确确认。
- 将本地数据默认页面改为当前状态与待处理变更视图。
- 将目录选择、复制选项和重启影响收拢到一次变更确认流程。
- 为设置页补齐加载、空数据、提交中、成功、失败和待重启状态。
- 完整覆盖焦点、键盘、明暗主题、目标尺寸和视觉回归。

## 不在范围

- 新增设置分类或与现有产品无关的开关。
- 将 Provider、数据库、上传和生成图片拆分到独立目录。
- 修改 Provider、存储位置或迁移 API。
- 修改 SQLite schema、相对文件路径或启动时数据根解析。
- 自动重启应用、删除旧数据目录、云同步或多设备迁移。
- 用自定义弹窗替换原生 `<dialog>`，或引入前端框架、路由和构建器。

## 已选方案与取舍

### 采用：列表管理 + 按需弹窗编辑

Provider 页面默认只显示配置列表、状态和新增命令。新增或编辑是一次独立任务，进入原生对话框完成。该方案最接近 Codex Desktop，也能把浏览、编辑和危险操作分开。

### 未采用：精修主从布局

主从布局适合高频编辑大量 Provider，但会保留管理后台感，并让表单持续占据主内容区。Image Tools 当前 Provider 数量和编辑频率不足以抵消这一代价。

### 未采用：页面内展开编辑

展开编辑减少一次弹窗，但会让页面高度、校验错误和删除确认互相影响，难以保持稳定的扫描节奏。

## 设置壳

设置继续作为覆盖主工作台的独立工作区，不增加客户端路由。设置壳由固定分类导航和受控宽度的内容区组成：

- 左侧导航在宽视口保持约 `180-196px`；`960x640` 下允许收紧，但分类文字和图标不得截断。
- 选中项使用中性表面色与正常文字色，不使用大块蓝色背景。
- 主内容阅读宽度控制在约 `620-660px`，在可用空间内居中，不横向铺满。
- 页面标题使用紧凑桌面层级；内容区不使用浮动卡片或卡片嵌套。
- 分组主要通过标题、留白和细分隔线建立层级。
- 图标使用现有本地 Lucide 资源；纯图标控件保留可访问名称和 Tooltip。
- 明暗主题沿用现有 CSS token，不建立独立的设置页配色系统。

导航保留 `Provider` 与 `本地数据` 两项。本地数据页面正文使用“工作区数据位置”，明确所有耐久数据作为一个整体迁移。

## Provider 页面

### 默认列表

页面头部显示 `Provider`、一句用途说明和带加号图标的“添加 Provider”命令。列表使用无卡片的行布局，每行稳定展示：

- Provider 名称。
- 默认模型。
- `API Key 已配置` 或未配置状态，不显示任何密钥内容。
- 当前默认 Provider 的中性标签。
- 一个更多操作按钮。

点击行进入编辑；更多菜单提供“编辑”、“设为默认”和“删除”。当前默认项可以继续编辑和删除，后端现有语义保持不变。删除成功后若列表为空，Composer 继续使用现有“未配置 Provider”状态。

### 空、加载与失败状态

- 首次加载使用稳定高度的轻量占位，避免页面和按钮跳动。
- 没有 Provider 时显示简洁空状态与“添加 Provider”命令，不渲染空表单。
- 列表加载失败时在 Provider 内容区显示错误和“重试”，不以 Toast 作为唯一反馈。
- 列表操作失败时保留现有列表，并在列表区域显示可读错误。

### 新增与编辑对话框

新增和编辑共用一个原生 `<dialog>`，字段保持现有合同：

- 名称。
- Base URL。
- API Key。
- 默认模型。
- 是否设为默认 Provider。

编辑时 API Key 永不回显；已保存密钥以状态文案表达，留空表示保持不变。二元的默认状态使用清晰的开关或复选控件，但不得使用未经样式处理的浏览器默认外观。

提交时保存按钮进入稳定的禁用/处理中状态，防止重复请求。成功后关闭对话框、刷新列表和 Composer Provider 状态，并将焦点恢复到原行或“添加 Provider”按钮。失败时对话框保持打开、保留用户输入，并在表单内显示错误。

### 删除确认

删除使用独立确认对话框，必须包含 Provider 名称和不可撤销说明。确认按钮使用危险样式；取消、关闭和 Escape 都不得执行删除。成功后关闭确认对话框并刷新列表，失败则留在确认对话框内显示错误。

## 工作区数据位置

### 单一数据根

工作区数据目录继续作为一个整体包含 Provider、会话、生成记录、参考图、生成图片和兼容设置。现有 `workbench.sqlite3` 相对路径、`images/`、`uploads/` 与 `settings.json` 不拆分。

稳定的启动定位文件继续单独保存在系统配置目录中。该技术性引导文件不作为用户可选的数据分类，也不在设置页提供独立位置。

### 默认状态页

页面标题为“本地数据”，正文分组标题为“工作区数据位置”。默认页面展示：

- 当前生效目录和“使用中”状态。
- “更改位置”命令。
- 工作区数据包含内容的简短说明。
- 可选的待处理目标目录和“等待重启”状态。

默认页面不长期展示空路径输入、复制复选框或应用按钮。没有待处理变更时显示克制的空状态；存在待处理变更时，当前目录和目标目录必须同时可辨认，目标目录不能被误标为当前目录。

### 更改位置流程

1. 用户选择“更改位置”。
2. 桌面端优先调用现有原生目录选择器。
3. 选择完成后打开确认对话框，展示新目录、复制现有数据选项和重启影响。
4. Web 开发入口保留可编辑路径作为无 Tauri 环境下的回退与测试入口。
5. “复制现有会话和文件”默认选中；用户可明确关闭。
6. 用户提交后调用现有 `POST /api/storage-location`。
7. 成功后关闭确认对话框，重新读取存储状态，并在页面显示目标目录和“等待重启”。

说明文字必须明确：变更只在下次启动生效；启用复制时保留原目录；复制完成前不会切换当前数据根；应用内不会自动删除源目录。

存储接口失败时确认对话框保持打开，保留目录和复制选项，并就地显示后端中文错误。目录选择器自身失败也在同一对话框显示，不退回 Toast。

## 前端边界

保持现有职责分层：

- `frontend/index.html`：设置壳、Provider 编辑对话框、删除确认对话框和存储变更对话框的语义结构。
- `frontend/styles.css`：设置页 token 映射、布局、行、对话框、状态反馈、响应式和明暗主题样式。
- `frontend/ui.js`：Provider 行、菜单、空状态、加载状态和设置状态的纯 DOM 渲染。
- `frontend/app.js`：设置导航、对话框生命周期、Provider/存储请求、提交状态和焦点恢复。
- `frontend/workbench.js`：仅在需要新的纯状态转换或 payload helper 时调整，不承载 DOM 生命周期。

不得引入只服务于两个分类的客户端路由或通用设置框架。若现有 `app.js` 事件编排因新增三个对话框而变得难以理解，可提取设置专用的小型生命周期 helper，但不得进行无关重构。

## 交互与可访问性

- 设置入口继续记住具体 opener；退出设置后恢复其焦点。
- Provider 行、更多菜单、添加按钮和更改位置按钮均可通过键盘操作。
- 原生 `<dialog>` 负责焦点陷阱；打开时焦点进入第一个有效字段或确认操作。
- Escape 只关闭最内层临时界面：菜单、确认对话框或编辑对话框优先于完整设置页。
- 关闭对话框后焦点返回具体行或触发按钮；删除行后返回列表中合理的相邻项或添加按钮。
- 导航使用正确的 `aria-current`；加载、保存结果和错误使用命名状态区域。
- API Key 不写入 DOM 文本、前端草稿、错误信息或截图基线。
- 控件尺寸、标签和动态状态不得导致布局跳动或文字溢出。
- 现有 reduced-motion 行为继续适用于菜单、对话框和状态反馈。

## 视觉要求

- 延续主工作台的 Segoe UI 与 CJK 系统字体栈、克制中性色和细边界。
- 设置页不使用渐变、装饰性背景、浮动页面卡片或大面积单色强调。
- 卡片仅用于真正需要框定的对话框；列表和页面分组保持无框或只使用分隔线。
- 交互圆角不超过现有设计系统的 `6-8px`。
- `1280x860` 与 `960x640` 下内容、菜单和对话框不得横向溢出。
- 明暗主题必须具有相同的信息层级、焦点可见性和危险状态辨识度。
- 最终 Windows WebView2 截图仍是字体渲染和像素校准的验收边界。

## 错误与并发处理

- 所有提交命令在请求期间禁用，避免重复创建、删除或安排迁移。
- 请求失败不清空表单、不关闭对话框、不把目标目录标记为已生效。
- 对话框关闭或设置页退出后，迟到响应不得重新打开旧界面或覆盖新的编辑任务。
- Provider 刷新成功后统一更新列表、默认 Provider 和 Composer 选择，避免两个表面状态不一致。
- 存储变更成功后以重新读取的后端状态为准，不仅依赖提交响应中的本地推断。
- 原生目录选择取消属于无变化结果，不显示错误。

## 验证

### Node 与 DOM

- Provider 列表渲染名称、模型、默认标签和密钥状态，但不渲染密钥。
- Provider 空、加载和错误状态具有稳定结构与重试命令。
- 行菜单触发编辑、设为默认和删除确认，不直接从删除菜单项发出 DELETE。
- 编辑对话框保留空 Key 的更新语义，失败时保留输入。
- 设置 Escape 关闭顺序和焦点恢复符合最内层优先规则。
- 存储状态区正确区分当前目录、待处理目录和无待处理变更。

### Playwright

- 从 Providers 入口打开 Provider 分类，从设置按钮打开本地数据分类。
- 覆盖 Provider 新增、编辑、设为默认、删除确认、取消删除、空状态和请求失败。
- 覆盖原生目录选择、Web 路径回退、复制选项、验证错误、成功后的等待重启状态。
- 在 `1280x860`、`960x640` 和明暗主题下检查设置壳、Provider 列表、Provider 对话框、本地数据页与存储确认对话框。
- 检查无横向溢出、对话框视口包含、菜单键盘行为、Escape 顺序和焦点恢复。
- 外部网络继续被测试环境拒绝，API Key 不进入截图或前端持久化。

### 完整回归

- 运行现有 Python、Node、Playwright 和 Cargo 检查。
- 有意更新设置页视觉基线后逐张检查 PNG。
- 在 Windows WebView2 上复核明暗主题、系统字体、原生目录选择器和两个目标窗口尺寸。

## 验收标准

- 设置页视觉层级与主工作台一致，不再出现大块蓝色导航、永久空表单或横向碎片化布局。
- 用户无需进入编辑即可扫描所有 Provider 的名称、模型、密钥状态和默认状态。
- Provider 新增、编辑、设为默认和删除均有完整、可恢复的交互状态。
- 用户无需面对常驻迁移表单即可理解当前工作区数据目录和待重启变更。
- Provider、会话和文件继续作为一个工作区数据集迁移，现有数据合同保持不变。
- 两种主题和两个目标尺寸通过行为、可访问性和视觉回归验证。
